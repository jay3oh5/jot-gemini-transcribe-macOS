# Compass's Observability Journal

## 2026-03-08 - String Classification for Diagnostic Fallback Counters
**Learning:** In privacy-conscious, local-only telemetry systems like `LiveStats`, raw internal session error messages are classified into coarse user-facing diagnostic buckets (e.g., `.neverOpened`, `.droppedMidSession`, `.truncated`, `.noFinal`). Fallthrough default buckets (such as defaulting unrecognized errors to `droppedMidSession`) can silently distort metrics when new or specific failure descriptions (like `activityEnd never flushed` or `activityEnd failed`) are emitted by session subsystems. Because "the connection dropped mid-sentence" implies network instability to the user while "the transcript did not arrive in time" indicates completion/deadline timeout, misclassification leads users and engineers to misdiagnose pipeline performance.
**Action:** When mapping internal lifecycle failure messages to metric dimensions, ensure end-of-turn flushing and signaling phrases (`activityend`, `flush`) are explicitly categorized alongside deadline and empty transcript conditions. Always back classification patterns with unit test assertions for all actual strings generated across session failure paths.
